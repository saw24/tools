Points d'attention (issus de l'export)
    Types d'indicateur en conflit de nom (avec la cible)

    DHIS2 impose un nom unique par Type d'indicateur. Les types ci-dessous portent le même nom qu'un type déjà présent sur l'instance cible, sous un autre UID — créer un doublon échouerait à l'import. Ils seront automatiquement reliés à l'objet existant sur la cible.

      CREATE_AND_UPDATE est recommandé pour un premier import comme pour une resynchronisation.
      ALL annule tout l'import au moindre objet en erreur — plus sûr pour un paquet avec dépendances.
      MERGE évite d'écraser des champs non inclus dans le paquet sur un objet déjà existant sur la cible.

      Simulation (Dry Run)

      Cette étape envoie le paquet à /api/metadata?dryRun=true : DHIS2 valide chaque objet (références manquantes, formats invalides, expressions d'indicateur non résolues...) sans rien modifier sur le serveur.
